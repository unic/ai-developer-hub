Add a second tab to the Claude Console that re-pivots the same Anthropic data from workspaces to users. The existing redesigned /claude page becomes the "Workspaces" tab; the new /claude/users page becomes the "Users" tab. 1. Context

Spec 026 made the Claude Console workspace-aware: a KPI strip, a stacked daily chart, a 12-month trend, top-movers chips, per-workspace sparklines, and a drill-through route at /claude/workspaces/[workspaceId] that already renders a per-workspace "top users" panel. Crucially, that spec also landed migration 0018_anthropic_sync_workspace_id, which added anthropic_sync_status.resolved_workspace_id — the bridge column that makes per-user data join cleanly to a workspace without touching the largest fact table in the schema (anthropic_usage_metrics, src/lib/db/schema.ts:525-564).

With the workspace pivot solved, the operational questions left on the table are user-centric. Inspected live on 2026-05-18 with the production dataset — 41 provisioned users across 13 workspaces producing $1,820.40 MTD — these questions are concretely unanswerable from the current UI without manual aggregation:

  • Who is the most expensive user this month? The top spender today holds 17% of total org spend; you have to scan every workspace's top-users panel to find them.
  • Is spend concentrated? The top-5 concentration is currently 58% of org cost — a single number that has no home in the existing UI.
  • Which users are growing fastest? Workspace top-movers exist; user top-movers do not.
  • Who is provisioned but unused? 6 users have an active Claude license assignment but no resolved_api_key_id in anthropic_sync_status. Today this can only be found by cross-referencing license_assignments against the sync table by hand.

The schema work this requires is zero: the per-user-per-day-per-model grain in anthropic_usage_metrics plus the user-to-workspace mapping in anthropic_sync_status already cover every aggregation the Users page renders. The hourly Anthropic Admin API sync from spec 018 already populates these tables and already calls revalidateTag("anthropic-workspace-costs") on completion — the same cache tag the new actions will use.

Canonical user-list query

-- The one query that drives the whole Phase 1 page. KPI tiles are aggregates over it;
-- the Top 10 chart is the first 10 rows; the table is every row. See data-model.md.
SELECT
  u.id                                          AS user_id,
  u.email,
  u.name,
  u.circle,
  u.profile,
  u.status,
  s.resolved_workspace_id,
  w.name                                        AS workspace_name,
  w.display_color                               AS workspace_color,
  COALESCE(SUM(m.computed_cost_cents), 0)::bigint AS cents,
  COALESCE(SUM(
    m.uncached_input_tokens
    + m.cache_read_input_tokens
    + m.cache_creation_input_tokens
    + m.output_tokens
  ), 0)::bigint                              AS total_tokens,
  COUNT(DISTINCT m.model)::int             AS models_used,
  MAX(m.date)                                AS last_active,
  BOOL_OR(m.pricing_resolved = false)       AS has_unresolved_pricing
FROM users u
LEFT JOIN anthropic_usage_metrics m
       ON m.user_id = u.id
      AND m.date BETWEEN $1 AND $2
LEFT JOIN anthropic_sync_status s
       ON s.user_id = u.id
LEFT JOIN anthropic_workspaces w
       ON w.workspace_id IS NOT DISTINCT FROM s.resolved_workspace_id
WHERE u.id <> 0                              -- exclude LOCK_USER_ID sentinel
GROUP BY u.id, u.email, u.name, u.circle, u.profile, u.status,
         s.resolved_workspace_id, w.name, w.display_color
ORDER BY cents DESC, u.email ASC;        -- ties broken by email

IS NOT DISTINCT FROM on the workspace join is the same trick spec 026 used for the per-workspace top-users panel (src/actions/anthropic-global.ts): it treats NULL as a real value so users in the default workspace are not silently dropped. LEFT JOIN on anthropic_usage_metrics (not INNER) is deliberate — users with zero spend must still appear because the "users with no API key" KPI is meaningless if those rows are pre-filtered out.

Phase 1 wireframe — /claude/users (real proportions)

UX details & edge cases

  • Tab strip placement: sits below the page <h1> and the sync pill row, full content width. The sidebar entry stays a single "Claude Console" link — active matching is by route prefix so both tabs highlight it.
  • Top-spender tile: clicking it scrolls (anchor link, not a route change) to that user's row in the table and briefly highlights the row. The same anchor pattern is used by Phase 2's top-movers chips.
  • Top-5 concentration tile: renders — when fewer than 5 active users have any spend. The action returns null in that case to avoid a misleading "100%" reading.
  • "No API key" tile: the denominator is "active users with an active Claude license assignment" — not "every user in the system". Otherwise the count would include users without a Claude license, which is meaningless. The number on the tile is the count; the caption shows the denominator.
  • Hide $0 toggle: default ON, persisted to localStorage claude-users:hide-zero. A disclosure underneath the table reads "Show N hidden ($0)" and expands the rows.
  • Tokens column label: it is intentionally Tokens, not Requests. anthropic_usage_metrics stores only tokens; "requests" would be a fabrication.
  • Pricing-unresolved chip: when has_unresolved_pricing is true for a row, render an amber chip .chip.warn next to the cost value with tooltip "Pricing not yet resolved for at least one row — total may grow once the next sync runs".
  • Empty state — no data at all: render the same <EmptyState /> the Workspaces tab uses (src/app/claude/page.tsx:123-135) with users-flavoured copy.
  • Empty state — filtered: when users.length === 0 after filtering, render a small "No matching users" panel with a "Clear filters" button.

Risks

  • Per-user totals will not reconcile with workspace totals (separate Anthropic endpoints, separate rounding). Mitigation: do not claim authoritative org-spend on the Users tab — that signal lives on the Workspaces tab. Footnote on the page.
  • Top-5 concentration unstable when fewer than 5 active users — render — rather than a misleading 100%.
  • Forgetting to exclude LOCK_USER_ID = 0 from a single query would silently produce a phantom row labelled "user 0". Mitigation: re-export the constant from src/lib/anthropic-sync.ts and lint-grep for any literal user_id <> 0 outside this file.

Acceptance criteria

  • Navigating to /claude/users as an admin renders the page; non-admins are redirected to /.
  • The header tab strip renders on both /claude and /claude/users and highlights the active route.
  • KPI strip renders four tiles in the order: Active users · Top spender · Top-5 concentration · Users with no API key.
  • Top 10 chart shows up to 10 users by cost DESC; each bar is filled with the user's resolved-workspace display_color; users without a resolved workspace get muted grey.
  • Users table is sortable on every numeric column; default sort is Cost DESC with email ASC as tiebreaker.
  • "Hide $0 users" toggle is checked by default and persists across reloads via localStorage at key claude-users:hide-zero.
  • Pricing-unresolved rows render an amber warning chip adjacent to the cost cell.
  • Top-spender tile click scrolls the user's row into view and applies a brief highlight.
  • Filtered-to-zero state shows "No matching users" with a Clear-filters button; data-empty state reuses the Workspaces empty state copy.
  • Every new server action is wrapped in unstable_cache with tag "anthropic-workspace-costs".

Daily-by-user query

-- Re-pivot of getDailyTotalsByWorkspace from spec 026 — same shape, GROUP BY user_id.
-- Top-5 + Other rollup happens in the action, not the SQL, so PG doesn't sort all users daily.
SELECT
  m.date,
  m.user_id,
  COALESCE(u.name, u.email)              AS user_label,
  SUM(m.computed_cost_cents)::int        AS cents
FROM anthropic_usage_metrics m
JOIN users u ON u.id = m.user_id
WHERE m.date BETWEEN $1 AND $2
  AND u.id <> 0                       -- exclude LOCK_USER_ID
GROUP BY m.date, m.user_id, u.name, u.email
ORDER BY m.date, cents DESC;

Sparklines + Top movers query

-- Per-user 6-month sparkline source. Action pivots into Record<userId, monthly rows>.
SELECT
  m.user_id,
  date_trunc('month', m.date)::date     AS month,
  SUM(m.computed_cost_cents)::int       AS cents
FROM anthropic_usage_metrics m
WHERE m.date >= date_trunc('month', CURRENT_DATE - INTERVAL '5 months')
  AND m.user_id <> 0
GROUP BY m.user_id, date_trunc('month', m.date);

-- Top movers uses the same source, partitioned by 3-month window halves;
-- structure mirrors getTopMovers() from spec 026 verbatim, GROUP BY swapped to user_id.

Phase 2 — Distribution + Fastest growing + Daily-by-user

UX details & edge cases

  • Distribution histogram: bars are colour-graded — first three buckets in cool greys, $50–$100 amber, $100+ red — to reinforce that the right tail is the operational concern. Empty buckets render at zero height with the count still labelled.
  • Bucket boundary edges: half-open intervals [lo, hi) so a user with exactly $1.00 falls in the $1–$10 bucket; $0 is its own bucket so empty users are not lumped in with cents-only users.
  • Daily-by-user chart: top-5 + Other rollup happens in the action, not the SQL, so the per-day result set stays bounded even when the dataset grows. Colour by rank (no per-user display colour exists); same spectral palette the workspace chart uses for "Other".
  • Top movers: drops are filtered (positive delta only); $5 floor on the prior 3-month window suppresses huge percentages off tiny bases — exactly the same rule as the workspace top-movers. Clicking a chip seeds the table search input rather than navigating, so the admin can see the row in context.
  • Sparkline column: reuses the spec 026 primitive. Colour is muted grey (no per-user display colour); 6-month window; renders — for < 2 data points; aria-label summarises the trajectory.
  • < 6 months of history: sparkline renders the months that exist; top-movers may have fewer than 3 chips; histogram still renders all 6 buckets.

Risks

  • Sparkline rendering cost at 41+ rows. Mitigation: reuse the existing inline-SVG primitive (no Recharts overhead per row).
  • Bucket boundaries drift between SQL and UI if hard-coded twice. Mitigation: single source of truth in src/lib/claude-users-buckets.ts; lint-grep for ad-hoc bucket arrays.
  • Top-5 + Other rollup in the daily chart can hide a user who is huge on one day but small overall. Acceptable trade-off (reviewers can drill into the user via the chip below).

Acceptance criteria

  • Cost-distribution histogram renders 6 fixed buckets; bar counts sum to total active users.
  • Fastest growing users (6mo) chip strip shows up to 3 chips of positive growers only; chips filter the table when clicked.
  • Users table has a new "Trend" column with 6-month sparklines; fewer than 2 data points renders —.
  • Daily-by-user chart renders one stacked bar per day with top-5 users + Other; hovering a bar shows per-user breakdown.
  • Bucket boundaries are exported from src/lib/claude-users-buckets.ts and reused in both the SQL and the histogram axis labels.
  • All four new actions reuse the "anthropic-workspace-costs" cache tag.
Phase 3 · Commit 3

Per-user drill-through

New route /claude/users/[userId] mirroring the workspace drill page at /claude/workspaces/[workspaceId]. Reachable from the Phase 1 Top 10 bar chart and users table, from the Phase 2 top-movers chips, and from the existing workspace top-users panel (whose target="_blank" link to /profile gets rewired in this commit).

Schema decision (resolved — no migration needed). Everything per-user joins through tables that already exist: anthropic_usage_metrics at (user_id, date, model) grain, plus anthropic_sync_status.resolved_workspace_id from spec 026 migration 0018.

Parallel to spec 026 Phase 3. The same patterns and components are mirrored: route parsing, admin gate, notFound() for invalid IDs, KPI strip composition, daily chart, model breakdown, breadcrumb back. Where spec 026 used the "default" URL sentinel for SQL NULL, this spec parses userId as an integer (rejecting LOCK_USER_ID = 0 and non-positive values).

Full caveats — per-user totals not summing to workspace totals, mid-month workspace moves being retroactive, pricing-unresolved rows — are documented in data-model.md and surfaced in the page footnote.

Goal

When a user is in the Top 10, in Fastest Growing, or surfaced as a workspace's top user, an admin can click in and immediately see what that user is doing — daily pattern, model mix, twelve-month history, and the 5 highest-spend days.

Effort

~30–40 hours · 1 new route · 5 new components · 2 new server actions · existing TwelveMonthBarChart and KpiStrip primitives reused.

Depends on

Phase 1 (KPI strip is composed). Phase 2 makes the top-movers chips navigable here (small follow-up edit). Spec 026 Phase 3 (parallel structure, plus the WorkspaceTopUsers link gets rewired).

User stories

  • As an admin, when I see a user in the Top 10 or in Fastest Growing, I want to click in and see their daily pattern, model mix, and 12-month history.
  • As an admin, I want to see what model each heavy user is leaning on (Sonnet vs Opus vs Haiku) so I can suggest cost-saving substitutions.
  • As an admin, I want the existing workspace top-users panel to navigate to the new per-user page rather than opening /profile in a new tab — that profile page is the user's own self-service surface.
  • As an admin, I want back-navigation to return me to the Users tab with my circle/workspace filter intact.

Per-user detail query

-- Single user, selected month. Mirrors getWorkspaceDetail() from spec 026.
-- Daily totals (one row per date):
SELECT
  m.date,
  SUM(m.computed_cost_cents)::int            AS cents,
  SUM(
    m.uncached_input_tokens
    + m.cache_read_input_tokens
    + m.cache_creation_input_tokens
    + m.output_tokens
  )::bigint                                     AS tokens,
  BOOL_OR(m.pricing_resolved = false)         AS has_unresolved_pricing
FROM anthropic_usage_metrics m
WHERE m.user_id = $1                            -- $1 = userId (already guarded against 0)
  AND m.date BETWEEN $2 AND $3
GROUP BY m.date
ORDER BY m.date;

-- Model breakdown for the same period:
SELECT
  m.model,
  SUM(m.uncached_input_tokens + m.cache_read_input_tokens
      + m.cache_creation_input_tokens)::bigint  AS tokens_in,
  SUM(m.output_tokens)::bigint                 AS tokens_out,
  SUM(m.computed_cost_cents)::int            AS cents
FROM anthropic_usage_metrics m
WHERE m.user_id = $1 AND m.date BETWEEN $2 AND $3
GROUP BY m.model
ORDER BY cents DESC;

-- Top 5 days for the user in this period (dominant model = argmax(cost) per day):
WITH daily_by_model AS (
  SELECT m.date, m.model, SUM(m.computed_cost_cents)::int AS cents
  FROM anthropic_usage_metrics m
  WHERE m.user_id = $1 AND m.date BETWEEN $2 AND $3
  GROUP BY m.date, m.model
),
ranked AS (
  SELECT date, model, cents,
         ROW_NUMBER() OVER (PARTITION BY date ORDER BY cents DESC) AS r
  FROM daily_by_model
)
SELECT date,
       SUM(cents)::int                              AS total_cents,
       MAX(CASE WHEN r = 1 THEN model END)       AS dominant_model
FROM ranked
GROUP BY date
ORDER BY total_cents DESC
LIMIT 5;

UX details & edge cases

  • Route guards: parseInt(userId, 10) returning NaN, 0, or negative → notFound(). userId === 0 is explicitly rejected because LOCK_USER_ID = 0 is the sync sentinel, not a real user. Unknown user (no row in users) → notFound().
  • Per-user KPI tiles: 4 tiles using the spec 026 <KpiStrip />: (1) Total MTD · (2) MoM delta · (3) Projected month-end · (4) Top model + its % of the user's cost. The 4th tile replaces the org-level "Over 80% count" tile from the workspaces page.
  • Workspace chip in header: pulled from anthropic_sync_status.resolved_workspace_id. When null, render "Default workspace". When the user has no row in anthropic_sync_status at all, render "No API key" with an amber chip and skip all downstream queries (all zeros).
  • Profile tier chip: pulled from users.profile — boost / maxed / indie. Coloured by tier.
  • No usage data: daily chart + top dates render the same empty-state primitive as /claude/workspaces/[workspaceId]. KPI tiles still render with $0.
  • Per-user totals vs workspace total: the sum of this user's cents in this workspace will not exactly equal the workspace-level total for this user. Same reason as spec 026: different Anthropic endpoints, different rounding. Footnote on the model breakdown card.
  • Mid-month workspace move: the workspace chip reflects the user's current API key's workspace, so historical data is retroactively attributed. Footnote in the workspace chip tooltip.
  • Pricing unresolved: when getUserDetail reports hasUnresolvedPricing, the model breakdown card renders an amber chip and the KPI tiles get a "*" superscript.
  • Back navigation: breadcrumb uses next/link to /claude/users, preserving any ?circle= / ?workspace= filters that originated in the URL. Mirrors the workspace drill-page pattern.
  • Workspace top-users rewire: the existing link in src/components/claude/workspace-top-users.tsx currently does target="_blank" to /profile?userId=N. After Phase 3 it navigates same-window to /claude/users/N. Reconciliation footnote next to the table stays as-is.

Risks

  • Removing the existing target="_blank" changes admin habit — some admins may currently open profiles in a new tab. Mitigation: changelog entry in the PR; new in-tab nav is the consistent pattern across the rest of the dashboard.
  • Per-user totals not reconciling with the workspace total is high-likelihood / low-impact (documented in spec 026 and again here). Mitigation: footnote on the model breakdown card.
  • A user with no anthropic_sync_status row would crash a naïve detail query. Mitigation: getUserDetail returns zeros + the no-API-key state early when the join is null.

Acceptance criteria

  • Navigating to /claude/users/{N} as an admin renders the user's name + workspace + profile, a 4-tile KPI strip, a daily chart, a model breakdown, top 5 dates, and a 12-month history chart.
  • /claude/users/0 and any non-integer userId render the Next.js 404 page.
  • Unknown but valid integer userId renders 404.
  • Non-admins are redirected from this route to /.
  • Clicking a row in the Phase 1 Users table navigates here (no new tab).
  • Clicking a bar in the Phase 1 Top 10 chart navigates here.
  • Clicking a Phase 2 Fastest Growing chip navigates here.
  • The existing workspace top-users panel (workspace-top-users.tsx) no longer opens /profile in a new tab — it navigates same-window to /claude/users/N.

  • When the user has no resolved_api_key_id, all downstream queries are short-circuited and the page renders a clear "No API key" empty state.

  • <Sparkline /> (src/components/ui/sparkline.tsx) — drops into the Phase 2 Users table Trend column unchanged.

  • <SyncStatusPill /> — the same pill renders on both tabs and on the per-user page.

Cache & sync

  • Every new server action wraps in unstable_cache with tag "anthropic-workspace-costs" — historically named, but covers every action that reads anthropic_usage_metrics and friends.
  • The hourly cron sync from spec 018 already calls revalidateTag("anthropic-workspace-costs") on completion — no new revalidation wiring.
  • No schema changes, no migrations, no backfill. The whole feature is read-only over the existing aggregate.

LOCK_USER_ID sentinel

  • user_id = 0 in anthropic_sync_status is the global sync-lock sentinel (LOCK_USER_ID in src/lib/anthropic-sync.ts:23) — it is not a real user and the users table has no row for it.
  • Every new query in anthropic-users.ts includes u.id <> 0 (or m.user_id <> 0 when there's no users join).
  • The constant is re-exported from src/lib/anthropic-sync.ts in Phase 1 task T109 so both files reference the same source of truth.
  • The Phase 3 route additionally rejects userId === 0 from the URL with notFound().

Default-workspace handling

  • Anthropic's "default workspace" is represented as NULL in anthropic_sync_status.resolved_workspace_id.
  • Every workspace join uses w.workspace_id IS NOT DISTINCT FROM s.resolved_workspace_id so default-workspace users are not silently dropped.
  • The Users table renders a workspace cell of "Default workspace" (with no badge) when the join returns null.

Pricing-unresolved warning chip

  • anthropic_usage_metrics.pricing_resolved = false means model pricing was unknown when the row was synced. computed_cost_cents is best-effort until the next sync resolves it.
  • Every aggregate action returns a hasUnresolvedPricing boolean alongside the cents.
  • UI renders an amber .chip.warn next to affected cost cells with tooltip "Pricing not yet resolved for at least one row — total may grow once the next sync runs".

Authorization

  • /claude/users, /claude/users/[userId], and every action in anthropic-users.ts are gated by session.user.role === "admin" — identical to src/app/claude/page.tsx:28-31.
  • Server actions use requireAdmin() from src/lib/auth-helpers.ts; non-admin callers receive an empty payload (existing pattern from anthropic-global.ts).

Reconciliation footnote (renders on the Users tab footer and on each per-user page).

Per-user totals on this page come from Anthropic's usage-report endpoint and do not exactly reconcile with the workspace-level totals on the Workspaces tab — those come from the cost-report endpoint. Different rounding, different aggregation windows. Surface both as separate views; do not pick a winner.
