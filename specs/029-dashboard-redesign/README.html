Dashboard Redesign

Two mockups — one for admins, one for viewers — that bring the storytelling and density of the recently-redesigned reports (PR #91, #92) to the dashboard landing page, without overloading it.

Why

The current dashboard (src/app/page.tsx) is functional but flat. The admin variant shows five plain KPI cards and four navigation tiles — no trends, no anomalies, no story. The viewer variant shows three KPI cards plus a 5-row "recent assignments" list — useful, but it ignores the rich per-user signal we now collect (Claude API usage, cache efficiency, per-model spend, key health).

The recently-redesigned reports prove the design system can carry much higher density. This spec brings the same patterns to the dashboard — but tuned per role: admins get the org-wide telescope, viewers get the personal mirror.

Layout

  1. Greeting + context bar — date-range pill, "all sources synced 12 min ago" chip, export.
  2. Hero row (2/3 + 1/3) — Budget Health Hero with a YTD-vs-projected stacked bar across the 12 months and a ceiling tick; This Month at a Glance with a 30-day spend area and "today" marker.
  3. KPI grid (4 cards) — Active users, Active licenses (with utilization bar), Spend this month, Copilot acceptance. Each with delta badge, comparison line, sparkline / mini-bar series.
  4. Spend over time — single stacked monthly chart (Licenses · Anthropic API · Copilot seats), 12 months with the last 7 fading as forecast. Right rail shows YTD total + per-series share.
  5. What's happening (4 cards) — auto-generated insights: biggest mover, workspace approaching its limit, license capacity, sync health.
  6. Top tools + Recent activity (2/3 + 1/3) — top-5 tools (MoM badge, 12-mo sparkline, monthly cost, "running API" badge for Anthropic); 24h timeline of invoice ingestions, assignment changes, workspace thresholds, budget period closes.
  7. Jump to (slim footer) — the old navigation tiles compressed, each with a one-line health hint.

Viewer dashboard viewer

Click the preview to open viewer.html.

Design principle: the viewer dashboard is a personal mirror, not a stripped-down admin view. Don't hide admin widgets behind permission checks — replace them with information that's relevant to one person: my spend, my key, my tools, my activity. No org rollups, no peer comparisons, no totals I can't act on.

What viewers can access (per role enforcement)

  • User-scoped, read-allowed: own assignments (getAssignmentsForUser), own Claude API usage (getUserCostData), own profile / cost data (getProfileData), theme preference.
  • Admin-only, hidden: all-user lists, budgets/forecasts, Copilot org metrics, workspace alerts, ingestion/sync settings, invoices, claude/* admin pages.
  • Source: guarded by AuthGuard (src/components/auth-guard.tsx:23) and requireAdmin() (src/lib/auth-helpers.ts:12); cost actions self-check at src/actions/anthropic-usage.ts:47-56.

Layout

  1. Greeting + key-health chip — "Hi Tobias", plus a live "Claude API · key healthy · last call 8 min ago" chip, plus a profile shortcut. Today the dashboard doesn't tell a viewer whether their key still works — this is the #1 thing to fix.
  2. Hero row (1/3 + 2/3)
    • Identity card — avatar, name, email, role/profile/circle badges, "tools assigned" and "active licenses" tiles, plus a green "key configured and healthy" callout with a self-service rotate link.
    • My Claude API usage (30-day area chart) — daily spend, "today" marker, the same PR #91 tooltip pattern (color swatches, currency values per model). Right rail breaks the 30-day total by model (Sonnet / Opus / Haiku) with mini-bars + token counts + cache savings footer.
  3. KPI strip (4 cards) — Spend this month (with MoM delta + sparkline + license/API split footer), Tokens used 30d (with input/output mini-bar), My tools (count + initials chips), Today (current-day cost + per-hour micro-bar). All user-scoped.
  4. My tools & licenses table — tool, tier, status (active / trial-Nd-left), monthly cost, assigned date. The trial badge surfaces an expiring trial that today's plain list buries.
  5. Recent activity on your account (2/3) + Available tools (1/3)
    • Recent activity is the same timeline pattern as the admin dashboard, but filtered to events that involve the current user: assignments granted/revoked, tier changes, key rotations, profile updates.
    • Available tools is new — a short list of tools the user doesn't have, with a "Request" button. Replaces the empty space where admin sees org-wide insights.
  6. Tip footer — a single contextual hint (e.g. "Caching cut your Sonnet costs by ~38% — keep system prompts stable") generated from the user's own usage data.

What's intentionally absent for viewers

  • No org spend / budget / forecast — viewer has no business with the CHF 180k ceiling.
  • No "biggest mover" / workspace alerts / sync health — admin-only signals.
  • No Copilot acceptance KPI — Copilot data is org-wide and currently admin-gated; per-user Copilot stats would need a new query.
  • No "all users / top spenders" — never visible to viewers.

Data wiring (sketch)

All numbers can come from existing actions; no schema changes are needed.

Admin

  • Budget hero, progress bar, projection → getBudgetReportData() (reuse forecast).
  • This-month snapshot → same source, current period only.
  • KPI grid → getReportOverviewData() already returns totalActiveUsers/Licenses, MoM previous, and expectedMonthlySparkline. Add a 28-day acceptance series from getCopilotOverview().
  • Spend over time → periodsWithActual (licenses + running API) + monthly Copilot snapshots; forecast from src/lib/forecast.ts.
  • Insights — biggest-mover & capacity already in getStaticInsights(); workspace-limit insight from getActiveAlerts() (already exists, just not surfaced here); sync health from syncEvents (currently untapped).
  • Recent activity → union of ingestionLog (newest 5), licenseAssignments (newest 3), syncEvents warnings, budgetPeriods close events.

Viewer

  • Identity card + badges → getProfileData(userId) (src/lib/profile-data.ts:184) returns name, email, role, circle, profile.
  • Key health chip + green callout → derive from licenseAssignments.apiKeyEncrypted presence + most recent anthropicUsageMetrics timestamp. "Last call N min ago" needs a tiny new query: latest requestedAt for this user.
  • 30-day usage area → getUserCostData(userId) already returns dailyBreakdown with {date, models[{model, costCents, inputTokens, outputTokens}]}.
  • By-model rail (Sonnet/Opus/Haiku) → roll up dailyBreakdown by model.
  • Cache savings footer → derive from cacheReadInputTokens vs uncachedInputTokens on anthropicUsageMetrics (currently untapped per-user signal).
  • KPI strip → all derived from getUserCostData + getAssignmentsForUser; "Today" is dailyBreakdown last entry.
  • My tools & licenses table → getAssignmentsForUser(userId). Add trial badge by checking tier name or a new boolean (out of scope here).
  • Personal activity timeline → changeHistory filtered to entries where userId = current, ordered DESC; small new selector needed.
  • Available tools → getTools() minus user's assigned toolIds. "Request" needs a new lightweight workflow (out of scope for the mockup — could be an email or a row in a new access_requests table).

Intentionally one click away

So the dashboard stays a landing page and not a second reports page:

  • Per-workspace Anthropic detail and model-level breakdown (admin: /claude; viewer: /profile).
  • Plan-vs-actual + forecast cumulative charts (admin /reports/budget).
  • Spend-by-circle table (admin /reports).
  • Full sortable Copilot table (admin /copilot/analytics).
  • Full ingestion history (admin /admin/ingestion).
  • Full personal assignment / activity history (viewer /assignments + /profile).

Open questions

  • Should the viewer dashboard be the new default landing for non-admins, or should we keep the "redirect viewers to /profile" pattern some other apps use? Mockup assumes the former.
  • Is the "Available tools · Request access" panel worth the new workflow it implies (notification, approval state, history)? If not, drop it and widen the activity timeline.
  • "Last call N min ago" requires either a tiny new query or a value precomputed during the Anthropic sync. Which?
  • For non-Anthropic users (no API key), the whole hero collapses to mostly empty state. Need a designed empty state: "You don't have Claude API access — here's what you can still do."
  • Date-range selector on the admin dashboard, or always "current month + YTD context"? Mockup assumes the latter; viewer keeps a 7/30/90d switcher because the usage chart is the centerpiece.
