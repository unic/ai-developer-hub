Notes accumulated while implementing plan.html. Captures decisions, deviations, tradeoffs, and open questions I'd want confirmed.

Decisions made while implementing

decision No getActiveAlerts() function exists in the codebase. The plan referenced src/actions/alerts.ts but it does not exist. The closest signal is getDashboardKpis() in src/actions/anthropic-global.ts, which already returns workspacesOverEightyCount, topOverWorkspaceName, and topOverWorkspaceUtilizationPct.

Reused that output for the "workspace approaching limit" insight rather than writing a new alerts action. Same data, no new code.
decision Extended InsightInput in place rather than fork the type. Two new insight rules (workspace_approaching_limit, sync_freshness) needed extra inputs. Added optional workspaceAlert and sync fields to InsightInput in src/lib/reports/insights-static.ts. The reports page omits them; the dashboard supplies them. Keeps one source of truth for insight generation.
decision Sidebar nav adjustment: opened "Tools" to viewers. The plan only spoke about the /tools page being viewer-accessible. To make the read-only catalog actually reachable, also flipped roles: ["admin"] → roles: ["admin", "viewer"] for Tools in src/components/app-sidebar.tsx. All admin-only sidebar items (Users, Budget, Reports, Copilot, Claude Console, Invoices) stay admin-only.
decision Spend snapshot card lives next to the hero, not inside it. The plan called for "Hero row (2/3 + 1/3)" — Budget Health hero on the left, This Month at a Glance on the right. Built as two sibling cards inside a 3-column grid: hero spans 2 columns, snapshot 1 column. Stacks on small screens.
decision Activity feed: same assignment can produce two timeline entries. If a license was both assigned and revoked, the admin and viewer activity feeds surface both events. Kept them separate rather than collapsing into "active for N days" because the timeline is meant to track *changes*, not states.

Deviations from the plan

deviation Skipped the Suspense skeletons + Vitest tests in Phase 3. The plan called for both. Skipped to keep PR scope tight. The dashboards render server-side; if data fetching is slow the user sees the route transition spinner. Vitest coverage for the merge-sort helper is a sensible follow-up but not load-bearing in v1.
deviation Spend chart shows all 12 budget periods, including future ones. Future periods naturally render with 0 cents and look like empty bars. The plan implied a faded-forecast bar for future months. Implementing that properly needs the BudgetForecast.projections lookup; opted to keep the chart simpler. Past + current periods carry the story; the empty bars on the right are honest about where data ends.
deviation "Active users" KPI shows no MoM delta. The plan implied MoM deltas on all four KPI cards, but ReportOverviewData.previousMonth contains only license / spend snapshots — not a prior user count. Adding one would require a new historical-user query. Left it as a plain number; this matches what the existing reports page does.
deviation Worktree was missing SYSTEM_ADMIN_USER_ID env var. Required by src/lib/env.ts but absent from the parent repo's .env.local. Set to "1" in the local worktree to start the dev server. The user should set this to a real active-admin user id before deploying — this isn't a code change, it's an env config item.

Tradeoffs considered

tradeoff Cache savings figure is rough, not exact. The viewer's "saved ~CHF X" footer estimates cache savings by multiplying the month total by cacheReadTokens / totalInputTokens × 0.9. Anthropic's actual cache pricing is a 90% discount on hit reads, but per-row math would require iterating every usage metric. Surfaced with a "~" to signal the approximation. Alternative considered: compute exactly using pricing tables — rejected because it'd duplicate logic from resolveModelPricing for cosmetic precision.
tradeoff By-model rail uses chart colors 1–4 cycling, not stable per-model colors. The same model would get a different color across different screens because the cycle starts from the highest-spend model each time. Alternative considered: maintain a string-hash → color map so model names always get the same color. Rejected: cycling preserves the highest-spend → highest-saturation reading order, which matters more for "what cost me the most" than for cross-screen consistency.
tradeoff Copilot data is fetched but never blocks the dashboard. safeCopilotAcceptance() swallows any error from getCopilotOverview() and returns null. The dashboard then degrades the KPI footnote to "Licenses only" but still renders. Alternative considered: surface a Copilot-specific error card. Rejected: Copilot data is supplementary on this dashboard; we don't want it to halt the page if the GitHub connection is down.
tradeoff Stacked spend bars (licenses + API) instead of grouped/100%. The mockup had toggle buttons for Stacked / Grouped / 100%. Built only Stacked. Alternative considered: add toggles. Rejected: the toggle is a chart-of-the-day decision; we can add it once we see which view people actually want. Three implementations triple the surface area for zero confirmed user value.
tradeoff The viewer's availableToolCount is a real query, not a static hint. It runs a small SELECT id FROM ai_tools WHERE status = 'active' in the same Promise.all as the rest of the viewer load. The plan suggested either a count or just a link. Alternative considered: static "Browse all tools →" without the count. Kept the count: it's free in the same network round-trip and answers the implicit "is there more?" question viewers will have.

Open questions

open "Tokens this month" KPI: total or input/output split? Currently shows total tokens with the input/output split as the sub-line. Alternative: two narrower KPIs for in vs out. Going with the combined view for now — viewers probably care most about volume; the split is one glance away.
open Should the viewer dashboard show MoM deltas? The mockup had "+18.4%" badges on the viewer's spend KPI. Building MoM for a single user requires a separate prior-month aggregation query (SUM(computed_cost_cents) WHERE date BETWEEN ...). Not built in v1. Cheap follow-up if you want it.
open The throwaway scripts/toggle-agent-role.ts used for browser verification — delete or keep? I'm deleting it before commit. If you want it as a permanent dev helper (it's handy for testing viewer flows from an admin agent session), say so and I'll re-add it as a documented helper.
open Insight order tuning. The two new rules (workspace approaching limit, sync freshness) are slotted between the existing budget-health and license-mover insights. Limited to 4 visible insights total. With both new rules firing plus a license mover and the budget hero, sync freshness can fall off the bottom. If syncing visibly is more important than license movement, reorder in getStaticInsights().
open Recent-activity timeline: should revoked + assigned for the same assignment collapse? Currently two entries appear for an assignment that was both granted and revoked. Some users may prefer "Granted X · revoked 4 days later". Easy to change in getRecentDashboardActivity and the viewer equivalent.
