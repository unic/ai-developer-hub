H2 Forecast Presets & Claude Billing Toggle

Evolve the Budget / Cost Forecast Simulation (spec 036) to model the org's actual H2 2026 plan: sunset Claude Console API access fast (down to a few applications and a few users), ramp Claude seats hard (+10–20 seats per period at a ~40% Premium share), let GitHub Copilot drift down very slowly or hold flat, and keep Cursor and Microsoft Copilot as-is. The three generic presets (Conservative / Expected / Aggressive) are replaced by three H2-migration variants of that plan. Additionally, the Claude seats line gets a Monthly / Yearly billing toggle — yearly commitment prices a Standard seat at $20 and a Premium seat at $100, versus $25 / $125 on monthly billing.

Drafted 2026-06-12 · author: T. Studer · branch: 040-h2-forecast-presets · builds on spec 036 · estimate: ~1 dev day

No data-layer or schema change. Presets are engine constants; the billing toggle is a pure price transform on prices the loader already supplies. The whole feature lives in the projection engine (src/lib/scenarios/budget-forecast.ts), the client UI, and the unit tests.

1 · Goal & scope

In scope

  • Replace FORECAST_PRESETS (Conservative / Expected / Aggressive) with three H2-migration presets — H2 Gradual, H2 Plan (the central prediction, new default), H2 Accelerated — encoding the fade-API / ramp-Claude-seats / hold-the-rest strategy at three speeds.
  • A Monthly / Yearly billing toggle on the Claude seats control row. Yearly = $20 Standard / $100 Premium effective per month; monthly = $25 / $125 (the live tier prices). Engine-level so every figure (tiles, ghost lines, charts, tables, verdict) reflects it.
  • Billing choice persists across preset switches: it's a procurement assumption, not a scenario lever, so all four tiles compare under the same cadence. Note this is new behavior with no existing analogue — clicking a tile today resets the edited ceiling to the live one, and that ceiling behavior is kept; the resulting asymmetry (tile click resets ceiling, keeps billing) is deliberate (§8).
  • Updated unit tests: new hand-computed preset anchors on the frozen fixture + billing-factor coverage.

Out of scope

  • No DB schema change; no new yearly tiers in access_tiers. The yearly price is a modelling assumption (§3), not a billing record.
  • No change to the data loader (budget-forecast-queries.ts) — seats, prices, and burn baselines come from the same live queries.
  • No lump-sum annual payment modelling — yearly billing is smoothed to an effective per-period rate (§3).
  • Keeping the old generic presets alongside the new ones — explicitly replaced per the request.

2 · The three H2 presets

The H2 strategy, as stated: "fade out Claude console API access very fast, down to almost zero seats, maybe only having a few applications and a few users. The Claude seats will be increased drastically, like 10–20 seats per period, and the premium share should be rather high, like 35 to 40%. Maybe 40 would be good. GitHub Copilot will very very slowly fade out or stay flat, Cursor will stay flat, and Microsoft Copilot will also stay as is."

Three variants of the same plan at different migration speeds — keeping the slow / central / fast triad shape the UI already has (tiles, ghost lines, comparison rows), so the chart still tells a bracketed story:

Why compound decline for the API fade

A compound negative rate decays toward — but never hits — zero, which is exactly the brief: "almost zero seats, maybe only a few applications and a few users." From today's 42 active keys, over the ~7 remaining FY2026 monthly periods:

  • −25%/period → ≈ 5–6 keys at year-end (gradual)
  • −35%/period → ≈ 2 keys at year-end (the plan: a few apps + a few users)
  • −50%/period → ≈ 0.3 keys at year-end (hard cutover)

Burn growth stays 0% and the cap is off: the seat fade is the story; per-key burn of the surviving applications is held at today's average.

Why linear ramp for Claude seats

"10–20 seats per period" is a linear statement, so the three presets use +10 / +15 / +20. From 63 live seats that lands ≈ 133 / 168 / 203 seats at year-end — "increased drastically". Premium share: 35% on the cautious variant, 40% on the plan and the accelerated variant ("maybe 40 would be good").

Copilot's "very very slow" fade

Flat on the gradual variant ("or stay flat"), −1 seat/period on the plan (72 → ≈ 65), −2/period accelerated (72 → ≈ 58). Cursor and MS Copilot stay flat everywhere.

Key rename, not key reuse. The preset keys become h2Gradual | h2Plan | h2Accelerated (replacing conservative | expected | aggressive). Reusing the old keys with new params would silently repoint everything that mentions "expected" (default seeding, reset affordance, tests) at different math — an honest rename surfaces every call site in the type checker. defaultInputs() seeds from h2Plan; the reset affordance becomes "Reset to H2 Plan".

3 · Billing cadence toggle

The Claude seats line gets a billing cadence: monthly (today's reality — the live access_tiers prices, $25 Standard / $125 Premium) or yearly (annual commitment — $20 / $100 effective per month).

Implemented as a factor, not hardcoded prices

$20/$25 and $100/$125 are both exactly 0.8 — a 20% annual-commitment discount. The engine applies CLAUDE_YEARLY_FACTOR = 0.8 to the loader-supplied stdPrice / premPrice when billing === "yearly". Verified against the live DB: the Claude tool has exactly two active tiers — Standard Seat 2500¢, Premium Seat 12500¢ — so the factor reproduces the stated yearly prices to the cent while staying anchored to the live tier prices if they're ever edited.

Semantics

  • Smoothed, not lumpy: yearly billing is modelled as an effective per-period rate (annual ÷ 12), not a January lump sum. The burn-up chart keeps its meaning; payment-timing modelling is out of scope.
  • Persists across presets: applyPreset threads the current cadence into inputsFromPreset(ds, key, billing), and the preset scoring path (presetInputs) does the same — tiles, ghost lines, and comparison rows are all recomputed under the current cadence, so every comparison is like-for-like. (The scoring half mirrors how the edited ceiling is spread into presetInputs today; the apply half is new behavior — the ceiling deliberately still resets on tile click, billing doesn't.)
  • Source of truth: the claudeSeats-kind tool's params.billing — located by kind === "claudeSeats", never by hardcoded key. The derived cadence joins presetInputs' memo dependencies (currently [dataset, inputs.ceilingCents]) so toggling re-scores the tiles.
  • Stamping rule: undefined ≡ "monthly" everywhere; inputsFromPreset stamps billing onto claudeSeats params only when it is "yearly", so default/monthly inputs stay deep-equal to pristine preset inputs.
  • Reset returns to monthly — "Reset to H2 Plan" restores the full default assumption set, exactly as it restores the live ceiling today.
  • Toggling cadence marks the plan Custom, same as editing the ceiling.
  • When yearly is active, the page footnote gains a clause noting the Claude line is priced at the annual-commit rate — the footnote otherwise implies all figures derive from live data.

4 · Engine changes

All in src/lib/scenarios/budget-forecast.ts — still pure, no new imports:

export type ClaudeBilling = "monthly" | "yearly";

// Yearly commitment: $25 → $20 Standard, $125 → $100 Premium — exactly 20% off
// the monthly tier price, expressed as a factor so it tracks the live tier prices.
export const CLAUDE_YEARLY_FACTOR = 0.8;

export type ToolParams = {
  /* …existing fields unchanged… */
  /** claudeSeats: billing cadence; undefined = "monthly". */
  billing?: ClaudeBilling;
};

// toolCostAt / currentMonthlyCost, claudeSeats branch:
const factor = p.billing === "yearly" ? CLAUDE_YEARLY_FACTOR : 1;
return Math.round(std * (tool.stdPrice ?? 0) * factor + prem * (tool.premPrice ?? 0) * factor);

// Presets: new keys + H2 parameter sets (§2 table).
export type PresetKey = "h2Gradual" | "h2Plan" | "h2Accelerated";

// Billing is orthogonal to presets — threaded in at application time so the
// client can keep the user's cadence when switching tiles:
export function inputsFromPreset(ds, key, billing?: ClaudeBilling): ForecastInputs;
//   → stamps `billing` on claudeSeats-kind tools' params ONLY when "yearly"
//     (undefined ≡ monthly, so monthly inputs stay deep-equal to pristine presets).
export function defaultInputs(ds): ForecastInputs;   // seeds from "h2Plan", monthly

seatsAt, projectForecast, computeTrendBand, and every dataset / result type are untouched. The negative-growth clamp (Math.max(0, …)) already handles the fading lines.

8 · Risks & decisions

TopicDecision / mitigation
Yearly price driftThe 0.8 factor is exact today (verified against the live tiers: 2500¢/12500¢). If yearly pricing ever stops being 20%-off-monthly, replace the factor with explicit yearly prices on ForecastTool — a noted follow-up, not speculatively built.
"A few seats" is a judgment call−25/−35/−50%/period are tuned so the central plan lands ≈ 2 keys at FY-end from today's 42. They're presets, not policy — every value remains live-editable, and the percentages are documented in the notes file for revision.
Preset ordering invariantThe "strictly ascending year-end" test is recomputed, not dropped — on the fixture the Claude ramp dominates, so gradual < plan < accelerated holds. If a future preset edit breaks monotonicity the test will say so loudly, which is the point.
Billing in ToolParams vs a top-level inputKept in ToolParams (claudeSeats only): the engine signature stays (tool, params, k), serialization is unchanged, and a hypothetical second seat-tier tool gets the lever for free. Persistence across presets is handled at application time (inputsFromPreset's third arg), not by global state.
Tile click: ceiling resets, billing persistsDeliberate asymmetry. The ceiling is part of a preset's "what-if" frame (a tile answers "this plan against the live budget"), so 036's reset-on-apply behavior is kept. Billing is a procurement fact about how the org pays for Claude seats — flipping tiles should not silently flip the contract. Surfaced in the notes file for review.
Quarterly budgetsGrowth values are per-period by design (036). On a quarterly budget "+15 seats/period" means per quarter — same pre-existing semantics, unchanged.
Stale preset referencesrg "conservative|expected|aggressive" across src/ + tests/ after the rename; the type-checker catches the rest via the PresetKey union.
