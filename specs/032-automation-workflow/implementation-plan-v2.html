Implementation plan v2

Executes the direction locked in mockups-v2.html: the ingest API receives role + profile and the Hub derives the tool from an editable mapping; Teams/Graph posting is postponed in favor of copy-paste snippets; approval creates the assignment (provision-first, Complete retired); unknown requesters are auto-created at approval; justification is first-class. Also fixes the two confirmed bugs from the July audit (form-payload rendering, queue search) and pays the deferred test debt.

2026-07-09 · branch: worktree-request-workflow · estimate ~4–5 dev days · no external dependencies (IT-112678 no longer on the critical path)

VerifiedCode facts this plan builds on

  • user_discipline enum already exists: developer | conception | business (schema.ts:50). The Form sends development — ingest normalizes development → developer.
  • user_profile enum already exists: boost | maxed | indie (schema.ts:45) — contains retired boost and lacks baseline, so requests get their own enum instead of reusing it.
  • users.passwordHash is NOT NULL (schema.ts:153); src/actions/users.ts:53 already establishes the pattern for login-less users: randomBytes(32).toString("hex") — never matches a bcrypt compare.
  • license_requests.requested_tool_id is NOT NULL (schema.ts:895-897) — must become nullable for indie/needs-decision.
  • ai_tools has no API-key flag (schema.ts:202-218) — new boolean needed.
  • completeRequest() already holds the assignment-creation transaction (duplicate-active guard, encryptApiKey(), first-write-wins, rollback) — it moves into approveRequest() rather than being rewritten.
  • Current migration head: 0028. This feature ships migration 0029.

  2. Single db.transaction():
    • If requesterUserId is null → insert user (name/email from request, discipline = requesterRole ?? "developer", profile from request when maxed/indie, role viewer, passwordHash = randomBytes(32).toString("hex"), no invite) and backfill requester_user_id. Handle the email-exists race with onConflictDoNothing + re-select.
    • Duplicate-active-assignment guard (existing logic, moved from completeRequest).
    • Insert license_assignments (tool, tier, user, assignedAt, apiKeyEncrypted = encryptApiKey(licenseCode) when provided).
    • First-write-wins UPDATE … SET status='approved', decided_by, decided_at, approval_message_md, assignment_id WHERE id=? AND status='pending_review'; 0 rows → throw RACE_LOST → rollback (assignment + any created user roll back too), return “already actioned by X”.

Rendering for preview/copy resolves it on demand from the decrypted assignment (admin-only server action getRequestMessage(requestId, { reveal })). If the admin hand-pastes a key into the editor, it is stored as typed — documented in the dialog hint.

  6. completeRequest() DELETED; rejectRequest/cancelRequest unchanged except Teams-call removal. completed enum value + completion_message_md stay for history; detail page renders legacy completed rows read-only as today.
