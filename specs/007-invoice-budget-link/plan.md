# Implementation Plan: Invoice–Budget Integration

**Branch**: `007-invoice-budget-link` | **Date**: 2026-03-05 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/007-invoice-budget-link/spec.md`

## Summary

When an invoice is saved to the archive, the system automatically finds the active budget period covering the invoice date and creates a linked billed cost entry — eliminating manual double-entry. The invoice model gains an optional vendor field (extracted by Claude) and a reference to the linked billed cost. A new bulk upload route accepts a zip of PDFs, extracts each one, and presents a batch review screen before saving.

### Phase B — Auto-Link Logic (P1 core)

Depends on Phase A.

#### B1 — Add `findActivePeriodForDate` utility

Location: `src/actions/invoices.ts` (internal helper, not exported).

```typescript
async function findActivePeriodForDate(
  invoiceDate: string
): Promise<{ id: number; periodLabel: string } | null>
```

Drizzle query:
```typescript
db.select({ id: budgetPeriods.id, periodLabel: budgetPeriods.periodLabel })
  .from(budgetPeriods)
  .innerJoin(annualBudgets, eq(budgetPeriods.budgetId, annualBudgets.id))
  .where(
    and(
      eq(annualBudgets.status, "active"),
      lte(budgetPeriods.startDate, invoiceDate),
      gt(budgetPeriods.endDate, invoiceDate)
    )
  )
  .orderBy(desc(annualBudgets.createdAt))
  .limit(1)
```

#### B2 — Add internal `insertBilledCostDirect` helper

Location: `src/actions/invoices.ts` (internal, not exported).

Inserts directly via `db.insert(billedCosts)` using the same fields as the public `createBilledCost` action but without re-running admin auth (already validated by the caller). Also calls `recordCreation("billed_cost", id, adminId)`.

Description format: `"Invoice {invoiceNumber}"` + ` — {vendor}` if vendor present. `vendorReference` set to `invoiceNumber`.

#### B3 — Update `saveInvoice` in `src/actions/invoices.ts`

After inserting the invoice row, run:
1. `findActivePeriodForDate(invoiceDate)` — if found:
   - Call `insertBilledCostDirect(...)`
   - `db.update(invoices).set({ linkedBilledCostId: costId }).where(eq(invoices.id, newId))`
   - Include `linkedPeriodLabel` in the return value
2. If not found: include `linkWarning: "No active budget period covers this invoice date."` in return

Update the `saveInvoice` return type to include optional `linkedPeriodLabel?: string` and `linkWarning?: string`.

#### B4 — Update `invoice-upload-form.tsx`

- Add `vendor` field using the existing `ConfidenceInput` component (same amber-border low-confidence UX)
- After `onSubmit`, read `result.linkedPeriodLabel` or `result.linkWarning` from the server action response
- Show success toast: `"Invoice saved. Linked to {periodLabel}."` or warning toast if `linkWarning` present
- Register `vendor` in the form with `register("vendor")`

### Phase C — Bulk Upload (P3)

Depends on Phase A and Phase B.

#### C1 — New API route: `src/app/api/invoices/bulk-upload/route.ts`

```typescript
export const maxDuration = 60  // Vercel function timeout for bulk processing
```

Flow:
1. `requireAdmin()` → 401 if not admin
2. Read request body as `ArrayBuffer` directly (not `request.formData()`) to handle large zips
3. Validate content-type header (`application/zip` or `application/x-zip-compressed`)
4. Use `unzipper.Open.buffer(Buffer.from(bytes))` to open zip
5. Filter entries to `.pdf` files; track skipped non-PDF names
6. Reject if 0 PDFs or > 50 PDFs (after filtering)
7. For each PDF entry (sequentially):
   - Read entry bytes
   - Generate `objectKey = invoices/{uuid}.pdf`
   - Upload to R2 via `PutObjectCommand`
   - Call `extractInvoiceFields({ objectKey })` from `src/lib/invoice-extraction.ts`
   - Push result to `results[]`
8. Return `{ results, skipped }`

Each result shape:
```typescript
{
  filename: string
  objectKey: string
  blobUrl: string
  extracted: InvoiceExtractionResult | null
  error: string | null
}
```

#### C2 — New server action: `saveBulkInvoices`

Location: `src/actions/invoices.ts`

```typescript
export async function saveBulkInvoices(
  inputs: CreateInvoiceInput[]
): Promise<ActionResult<BulkSaveOutcome[]>>
```

Iterates over `inputs`, calls `saveInvoice` for each (reusing all auto-link logic from Phase B). Collects per-item outcomes. Does not abort on individual failure.

#### C3 — New page: `src/app/invoices/bulk/page.tsx`

Admin-only (redirect to `/login` if not admin). Renders `<BulkUploadForm />`.

Add a "Bulk Upload" link/button to `src/app/invoices/page.tsx` nav area.

#### C4 — New component: `src/app/invoices/bulk/bulk-upload-form.tsx`

State machine: `"idle" | "uploading" | "reviewing" | "saving" | "done" | "error"`

**Idle state**: File input accepting `application/zip` + "Upload Zip" button.

**Uploading state**: Spinner. POST to `/api/invoices/bulk-upload` with zip as `application/octet-stream` body (not FormData, to avoid 4 MB limit).

**Reviewing state**: TanStack Table with columns:
- Filename
- Invoice Number (editable input, amber if low-confidence)
- Date (editable input, amber if low-confidence)
- Amount (editable number input, amber if low-confidence)
- Vendor (editable input, amber if low-confidence)
- Error (badge if extraction failed — still editable manually)

"Save All" button → calls `saveBulkInvoices`.

**Done state**: Summary table showing per-file outcome (saved / linked period / warning / failed). "Back to Invoices" link.

ARIA live region announces state transitions.

## Verification

### Unit tests (Vitest)
- `findActivePeriodForDate`: period found, no period, boundary date (last day of month), archived budget
- `insertBilledCostDirect`: correct description format with and without vendor
- `invoiceExtractionResultSchema`: accepts/rejects vendor variations
- `createInvoiceSchema`: vendor optional, passes without it

### Integration tests (Vitest + real DB)
- `saveInvoice` with matching active period → invoice saved, billed cost created, `linkedBilledCostId` set
- `saveInvoice` with no matching period → invoice saved, no billed cost, `linkWarning` returned
- `saveBulkInvoices` with 3 invoices (2 linked, 1 not) → correct per-item outcomes

### E2E tests (Playwright)
- Single invoice upload: upload PDF → vendor pre-filled → save → toast shows period label → period view shows cost
- Bulk upload: upload zip with 3 PDFs → review screen shows 3 rows → save → summary shows 3 outcomes
- No-match warning: upload invoice with out-of-range date → warning toast shown

### Manual smoke
- Upload a zip > 50 MB → reject with size error
- Upload a zip with 51 PDFs → reject with count error
- Upload a zip containing a `.txt` file alongside PDFs → txt skipped, PDFs processed
