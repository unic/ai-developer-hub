Claude API Spending — page redesign

Reorient /claude around three operational questions: are we over budget anywhere right now? where is the run-rate going? which workspace is growing fastest? The redesign ships in three phases, keeps the existing schema (no migrations in Phases 1 & 2), and reuses the hourly Anthropic Admin API sync from spec 018.

1. Context

/claude is admin-only (admin role gate; non-admins redirect to /). It aggregates Anthropic API cost data synced hourly from the Anthropic Admin API into the anthropic_workspace_costs table (per-workspace, per-date rows; see spec 018). Org billing budget lives in anthropic_org_config; workspace-level monthly caps in anthropic_workspace_limits; workspace metadata in anthropic_workspaces. Sync state is tracked by the userId = 0 sentinel row (per LOCK_USER_ID in src/lib/anthropic-sync.ts:23) in anthropicSyncStatus.workspaceSyncCompletedAt.

The current page surfaces a grand total, a single-series daily bar chart, an org billing card paired with a "Credit Balance" placeholder (the Anthropic API does not expose credit balance), and a workspace list sorted alphabetically. Inspected live on 2026-05-15 with 13 real workspaces, the layout buries the operational signal: "Automations" is at 105% of its $50 cap and has grown +413% over six months, but neither fact is visible without scanning every row or computing it mentally.

// src/lib/utils.ts — shared util
export function projectMonthEnd(
  mtdCents: number,
  daysElapsed: number,
  daysInMonth: number,
): number {
  if (daysElapsed === 0) return 0;
  return Math.round((mtdCents / daysElapsed) * daysInMonth);
}

Data flow

page.tsx (Server Component) calls getGlobalCostDashboard, getWorkspaceList, getOrgConfig, getDashboardKpis, and getSyncStatus in parallel via Promise.all. All five reuse the "anthropic-workspace-costs" cache tag. Plain JSON is passed to <GlobalMetricsClient>; the client component owns workspace/month filter state and re-fetches via useTransition on month change. The "Hide $0 + no limit" toggle is pure client-side filtering over the workspaces prop, with the preference persisted in localStorage at key claude-hide-zero-workspaces.

UX details & edge cases

  • KPI tile 3 (projected): if projectedMonthEndCents > orgBudget, the tile gets a red ring + warning icon.
  • KPI tile 4 (over 80%): warning palette when count > 0; lists the most-over workspace name underneath.
  • Stacked chart: with more than 8 workspaces, the legend collapses to "Top 8 + Other". Top-8 rule (decided in spec review): rank by SUM(cost_cents) for the selected period — re-computed per render based on the month being viewed; ties broken by workspace name ASC. Tooltip shows per-workspace breakdown for the hovered day. Color comes from anthropic_workspaces.displayColor (verified present, varchar(20)) with a deterministic palette fallback keyed by workspace ID so the same workspace always gets the same color across renders.
  • Workspace sort: (1) over 100% first, (2) over 80% next, (3) with-limit by utilization DESC, (4) no-limit by spend DESC, (5) $0+no-limit last.
  • Hide $0 toggle: default ON, persisted via localStorage. A "Show N hidden workspaces" disclosure expands the collapsed rows.
  • Empty data: existing empty state from spec 018 still renders; the KPI strip shows "$0" and the MoM tile shows "—".
  • Single workspace: stacked chart degrades cleanly to one series. Legend hides "Other".
  • Prior month $0: MoM delta tile renders "—" with caption "no spend last month" (avoids divide-by-zero nonsense).
  • Stale sync (>70 min): amber pill. KPIs still render from the cached data.

Risks

  • MoM percent unstable when prior month is near-zero. Mitigation: render null from the action, "—" in the UI when prior < $1.
  • Linear extrapolation for projected month-end can mislead on lumpy workloads. Acceptable for Phase 1; Phase 2 pacing chart provides better visual baseline.
  • 13+ workspace stack would produce an unreadable legend. Mitigation: top-8 + Other rollup is enforced server-side.

Acceptance criteria

  • Page title and sidebar nav read "Claude API Spending".
  • KPI strip renders four tiles in the order: Total MTD · MoM delta · Projected month-end · Over-80% count.
  • When any workspace exceeds 80% of its limit, the Over-80% tile renders in the warning palette and the workspace appears at the top of the list.
  • Daily chart renders one stacked bar per day with one segment per workspace; hovering a bar shows a per-workspace tooltip.
  • "Hide $0 + no limit" toggle is checked by default; toggling persists across reloads via localStorage.
  • The Credit Balance card no longer appears; the Monthly Billing Budget card spans the full content width.
  • Sync pill shows green ≤ 70 min, amber > 70 min, grey when never synced.

Phase 2 — Historical Trend card

UX details & edge cases

  • 12-month chart: bars exceeding the budget cap line get a red top stroke. Tooltip shows total + cap + over/under.
  • Pacing chart: current month bold; prior 3 months in cool greys. Tooltip locks to closest day-of-month across all series. Current line terminates at today; prior months extend to their actual end.
  • Fastest growing (label decided in spec review; was "Top Movers"): top 3 by positive % delta only — drops are filtered out. $5 floor on prior period to suppress huge percentages off tiny bases. All chips render with ▲.
  • Sparklines: 120×32 inline SVG (no Recharts). Hand-rolled <polyline> avoids 13× component overhead. Workspaces with < 2 months of data render —.
  • < 12 months of history: chart only renders months that exist; missing prior-month pacing series simply absent.
  • New workspace mid-month: sparkline shows partial data with a starting dot.

Risks

  • Cumulative pacing query is the heaviest in this phase. Mitigation: use SQL window functions, not JS reduction.
  • 13+ Recharts sparkline instances would hurt render time. Mitigation: hand-rolled inline-SVG primitive in src/components/ui/sparkline.tsx.
  • Top movers can mislead when prior figure is tiny — already mitigated by the $5 floor.

Acceptance criteria

  • Historical Trend card renders below the daily chart with three views: 12-month bars · Cumulative pacing · Fastest growing.
  • 12-month bar chart shows a horizontal budget cap line and visually marks any month that exceeded it.
  • Cumulative pacing chart shows four series (current + 3 prior); current series terminates at today.
  • "Fastest growing" strip shows up to 3 workspaces by positive % delta (no decliners), filtering out workspaces with < $5 in prior period.
  • Workspace list has a new "Trend" column with a 6-month sparkline per workspace; < 2 data points renders "—".
  • All new queries reuse the existing "anthropic-workspace-costs" cache tag.
Phase 3 · Commit 3

Workspace drill-through

New route /claude/workspaces/[workspaceId] showing per-workspace daily chart, top users, and model breakdown. Reachable from workspace rows and Top Movers chips.

Schema decision (resolved — no spike needed). The current anthropic_usage_metrics table has no workspace attribution. Anthropic's /v1/organizations/api_keys response includes a workspace_id per key, but the codebase's Zod schema (src/lib/anthropic-keys.ts:5-11) discards it.

Approach: extend orgApiKeySchema to capture workspace_id, then store it alongside resolvedApiKeyId via a new resolved_workspace_id column on anthropic_sync_status (1 row per user — tiny). Phase 3 queries join anthropic_usage_metrics → anthropic_sync_status → resolved_workspace_id. No backfill on the large usage table.

Full analysis and caveats in data-model.md.

Phase 3 — /claude/workspaces/automations

UX details & edge cases

  • Default workspace: reachable via /claude/workspaces/default (URL sentinel for SQL NULL). Page renders "Default Workspace" with no badge.
  • Not found: unknown workspace ID → notFound() from Next.js → 404 page.
  • Per-workspace KPI tiles (decided in spec review): reuse the Phase 1 <KpiStrip> with workspace-scoped props rendering (1) Total MTD · (2) MoM delta · (3) Projected month-end · (4) Utilization % (replaces the org-level "Over 80% count" tile). Mockup screenshot showed a Requests-count tile — that's overridden by this spec decision; the canonical 4 tiles are listed here.
  • No limit set: 4th KPI tile shows "No limit set" with an inline action to set one (reuses setWorkspaceLimit from Phase 1).
  • No usage data: daily chart + top users render empty states; KPI strip still renders ($0).
  • Per-user totals vs workspace total: the sum of per-user costs in this workspace will not exactly match the headline workspace cost. They come from different Anthropic endpoints (usage report vs cost report) with different rounding. Surface both as separate signals; do not try to reconcile them.
  • Mid-month workspace move: resolved_workspace_id reflects the user's current API key's workspace. If a user is moved to a different workspace mid-month, historical usage gets attributed to the new workspace. Footnote in the UI.
  • Back navigation: breadcrumb uses next/link to /claude?workspace={id}; parent <GlobalMetricsClient> reads the query param on mount.

Risks

  • Per-user → workspace attribution is derived via the Anthropic API key's workspace_id; reliable because Anthropic enforces 1 key = 1 workspace. The risk is that admin imports might leave stale resolved_workspace_id values — mitigation: re-resolve on every sync (cheap, sync already calls fetchOrgApiKeys).
  • The "default" URL sentinel needs round-trip testing. Mitigation: explicit unit test on the route parser.
  • anthropic_usage_metrics.model column is NOT NULL per src/lib/db/schema.ts:534 — no nullability mitigation needed (earlier draft worry retracted during spec review).

Acceptance criteria

  • As admin, navigating to /claude/workspaces/{id} renders the workspace name, KPI strip, daily chart, top users, and model breakdown.
  • Clicking a workspace row in Phase 1 list navigates here.
  • Clicking a Phase 2 Top Movers chip navigates here.
  • The default workspace is reachable via /claude/workspaces/default and renders without error.
  • Non-admins are redirected from this route.
  • Breadcrumb back-link pre-selects the workspace in the parent filter.

6. Cross-cutting concerns & shared helpers

Shared helpers (introduced in Phase 1, reused after)

  • projectMonthEnd(mtdCents, daysElapsed, daysInMonth) in src/lib/utils.ts — reused by org billing card & per-workspace KPI strip.
  • <SyncStatusPill /> — reusable wherever sync status is surfaced.
  • <KpiStrip /> — the same component renders both the org-level (Phase 1) and per-workspace (Phase 3) strips with different prop sets.
  • <Sparkline /> — Phase 2; should also replace any equivalent sparkline on /profile (existing user view).

Cache & sync

  • Every new server action wraps in unstable_cache with tag "anthropic-workspace-costs".
  • The existing hourly cron sync (spec 018) already calls revalidateTag("anthropic-workspace-costs") on completion — no new wiring needed.
  • getSyncStatus() bypasses the cache; it reads the sentinel row directly (sub-millisecond).

Authorization

  • /claude + all subroutes gated by session.user.role === "admin".
  • Phase 3 route guard mirrors the parent page guard (redirect to / for non-admins).
  • Server actions use requireAdmin() from src/lib/auth-helpers.ts; non-admin callers receive an empty payload (existing pattern).

Accessibility

  • All charts retain Recharts accessibilityLayer; sparkline primitive uses role="img" + aria-label with a textual summary.
  • KPI tiles use aria-describedby linking the value to its caption for screen readers.
  • Sync pill uses aria-live="polite" when the staleness state changes.

8. Rollout & risk register

Single-PR rollout

All 3 phases ship in one PR, organized as 3 sequential commits so review can be staged phase-by-phase:

  1. Commit 1 — Phase 1: visual reset, KPI strip, stacked daily chart, sync pill, full-width billing card, workspace re-sort. Standalone-functional even if commits 2 + 3 are reverted.
  2. Commit 2 — Phase 2: Historical Trend card + sparklines. Includes a perf assertion (cumulative pacing query < 200ms on dev DB).
  3. Commit 3 — Phase 3: schema migration (resolved_workspace_id) + sync extension + drill-through route. Migration runs first; ships before the UI that depends on it within the same commit so review sees the full vertical slice.

Gated rollout (feature flag) is not used: the page is admin-only and changes are additive. Internal-admin validation period of 1 week before announcing.
