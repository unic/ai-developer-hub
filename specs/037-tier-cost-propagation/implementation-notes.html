Stale tier-cost snapshots — reports show 0 after tier price change

Branch: fix/tier-cost-propagation · Started 2026-06-11

Symptom

A cost was added to the Microsoft Copilot access tier, but the Reports page (and dashboard) still show the tool's monthly spend as 0.

Root cause

license_assignments.cost_at_assignment_cents (schema.ts:249) is a price snapshot taken when a license is assigned. Every spend aggregation in the app sums this snapshot, not the live tier price:

Read siteWhat it computes
src/app/reports/page.tsx:52,69,96Reports overview: per-tool monthly cost, total monthly spend, prior-month comparison
src/actions/reports.ts:128–157Budget tab: per-tool per-period expected spend
src/actions/dashboard.ts:158,173,199,554Admin + viewer dashboards
src/actions/budget.ts:318,571Expected spend per budget period
src/lib/reports/circle-report.ts:25Per-user circle report

But updateTier (src/actions/tools.ts:296) only updates access_tiers.monthly_cost_cents. Existing active assignments keep their old snapshot (0 in this case), so every report keeps summing 0. The tier was created while free → all Copilot assignments snapshotted 0 → price edit changed only the tier row.

Other places with the same bug

  • src/lib/copilot-sync.ts:103–108 — GitHub Copilot billing sync auto-updates a tier's monthlyCostCents when the plan price differs, and likewise never touches existing assignments. A GitHub price change would silently leave every synced seat at the old cost.
  • Existing data — assignments created while the tier price was wrong remain stale forever; code fixes alone don't repair them. Needs a one-time backfill.

Places checked and found OK

  • src/actions/assignments.ts:224–229 — changing an assignment's tier already re-snapshots the cost.
  • New assignments (manual, bulk import, license requests, copilot-sync seat creation) all snapshot the current tier price at creation.
  • Scenarios (src/lib/scenarios/*queries.ts) and MCP list_ai_tools read live access_tiers.monthly_cost_cents — always current.

Fix design

Chosen approach: propagate price changes to active assignments wherever a tier's price is mutated, plus a one-time backfill migration. Revoked/inactive assignments keep their historical snapshot (correct for past-period reporting).

Rationale: this matches the codebase idiom (cf. annual_budgets.totalAmountCents — "mutated … so existing read sites stay accurate without churn", schema.ts:278) and the existing behavior of updateAssignment, and it fixes all ~15 read sites at once instead of rewriting every aggregation to join access_tiers.

Caveats before running against production:

  • The backfill is an irreversible overwrite that bypasses the change-log. Capture the affected rows first: 
    SELECT la.id, la.cost_at_assignment_cents, t.monthly_cost_cents
FROM license_assignments la JOIN access_tiers t ON t.id = la.tier_id
WHERE la.status = 'active' AND la.cost_at_assignment_cents <> t.monthly_cost_cents;
  • Resolve which Neon branch DATABASE_URL points at before pnpm db:migrate (current .env.local → ep-little-frost, not the known prod endpoint).
  • Semantic shift: for active assignments, cost_at_assignment_cents now means "current tier price"; only revoked rows keep a true historical snapshot.
